2. Padrão Escolhido

Template Method — Padrão Comportamental GoF

O Template Method é um padrão de projeto comportamental que define o esqueleto de um algoritmo em uma operação, postergando a definição de alguns passos para subclasses. Ele permite que subclasses redefinam certos passos de um algoritmo sem alterar a estrutura geral do mesmo.

Definição formal (Gang of Four, 1994): "Define the skeleton of an algorithm in an operation, deferring some steps to subclasses. Template Method lets subclasses redefine certain steps of an algorithm without changing the algorithm's structure."

Classificação

  • Família: Comportamental
  • Escopo: Classe (usa herança)
  • Intenção: Invariância do algoritmo com variância dos passos
  • Participantes: AbstractClass (define o template) e ConcreteClass (implementa passos variáveis)

3. Problema Proposto

Sistema de Geração de Relatórios Corporativos

Uma empresa precisa de um sistema que gere relatórios financeiros em três formatos distintos: PDF, HTML e CSV. Cada formato é utilizado em um contexto diferente:

  • PDF: Impressão e arquivamento formal de documentos
  • HTML: Visualização em portais web internos da empresa
  • CSV: Importação em planilhas e ferramentas de Business Intelligence

Requisitos do Sistema

  • Cada relatório deve seguir sempre o mesmo fluxo de execução
  • O formato de saída (cabeçalho, corpo, rodapé) varia conforme o tipo
  • Novos formatos poderão ser adicionados no futuro
  • Deve ser possível adicionar novos passos ao fluxo sem grande esforço

Fluxo de Geração (invariante)

Sequência obrigatória para todos os formatos: [1] Coletar dados → [2] Processar dados → [3] Formatar cabeçalho → [4] Formatar corpo → [5] Incluir marca d'água (opcional) → [6] Formatar rodapé → [7] Exportar arquivo

Os passos 1, 2 e 7 são idênticos independentemente do formato. Apenas os passos 3, 4 e 6 variam de acordo com o tipo de relatório. O passo 5 é opcional (hook).

4. Por que a Solução Inicial é Inadequada

Na primeira versão do sistema (Versão 1 — Sem GoF), a abordagem ingênua consistiu em criar três classes independentes — RelatorioPDF, RelatorioHTML e RelatorioCSV — cada uma com seu próprio método gerar() contendo todo o fluxo.

Problemas Identificados

    processarDados();    // ← DUPLICADO nas 3 classes

// RelatorioHTML.java — mesma estrutura duplicada

    coletarDados();      // ← DUPLICADO

5. Aplicação do Padrão Template Method

5.1 Estrutura do Padrão

O padrão Template Method é aplicado por meio de uma classe abstrata RelatorioGerador que define o método template gerarRelatorio() como final, impedindo que subclasses alterem a ordem dos passos. Os passos que variam entre os formatos são declarados como abstract, obrigando cada subclasse a implementá-los.

5.2 O Método Template

// RelatorioGerador.java — Versão 2
public abstract class RelatorioGerador {

    public final void gerarRelatorio() {   // TEMPLATE — final!
        coletarDados();        // passo fixo (implementado aqui)
        processarDados();      // passo fixo (implementado aqui)
        formatarCabecalho();   // abstract — subclasse implementa
        formatarCorpo();       // abstract — subclasse implementa
        incluirMarcaDagua();   // hook     — opcional
        formatarRodape();      // abstract — subclasse implementa
        exportar();            // passo fixo (implementado aqui)
    }

    protected abstract void formatarCabecalho();
    protected abstract void formatarCorpo();
    protected abstract void formatarRodape();

    // Hook method — implementação padrão vazia
    protected void incluirMarcaDagua() { }
}

5.3 Implementação das Subclasses

Cada subclasse implementa apenas os passos que variam. O RelatorioPDF também sobrescreve o hook incluirMarcaDagua() para adicionar a marca "CONFIDENCIAL": 

// RelatorioPDF.java — apenas o que muda
public class RelatorioPDF extends RelatorioGerador {

    @Override
    protected void formatarCabecalho() {
        System.out.println("RELATÓRIO PDF - LANDSCAPE");
    }

    @Override
    protected void formatarCorpo() {
        // renderiza corpo em formato PDF
    }

    @Override
    protected void formatarRodape() {
        System.out.println("Página 1 de 1 | PDF/A");
    }

    // Sobrescreve o hook — marca d'água apenas no PDF
    @Override
    protected void incluirMarcaDagua() {
        System.out.println("[PDF] CONFIDENCIAL");
    }
}

5.4 Como o Padrão Resolve o Problema

7. Uso de Reflexão e Anotações

7.1 Motivação

Embora o Template Method da Versão 2 resolva o problema de duplicação, o método template ainda está acoplado aos nomes dos métodos em tempo de compilação. A Versão 3 elimina esse acoplamento usando anotações Java próprias e a API de reflexão para descobrir e invocar os passos dinamicamente.

7.2 Anotações Criadas

@PassoRelatorio

Marca um método como sendo um passo do algoritmo e define sua ordem de execução:

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface PassoRelatorio {
    int ordem();                               // posição no algoritmo
    String descricao() default "Passo";        // descrição legível
    boolean obrigatorio() default true;        // true = obrigatório / false = hook
}

@RelatorioConfig

Anota a classe com metadados do formato de relatório:

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
public @interface RelatorioConfig {
    String nome();
    String extensao();
    String versao() default "1.0";
    String descricao() default "";
}

7.3 Como a Reflexão é Utilizada

O ExecutorRelatorio realiza os seguintes passos em tempo de execução:

public void executar(RelatorioGerador gerador) {
    Class<?> classe = gerador.getClass();

    // 1. Lê metadados da classe via @RelatorioConfig
    RelatorioConfig config = classe.getAnnotation(RelatorioConfig.class);

    // 2. Descobre métodos anotados com @PassoRelatorio
    List<Method> passos = descobrirPassos(classe);

    // 3. Ordena pelos campos 'ordem'
    passos.sort(Comparator.comparingInt(
        m -> m.getAnnotation(PassoRelatorio.class).ordem()
    ));

    // 4. Invoca dinamicamente — sem conhecer os nomes!
    for (Method metodo : passos) {
        metodo.setAccessible(true);
        metodo.invoke(gerador);
    }
}

7.4 Como isso Reduz o Acoplamento

AspectoVersão 2 (Template Method)Versão 3 (Reflexão + Anotações)
Executor conhece nomes dos métodos?Sim — chamadas diretasNão — descobre via @PassoRelatorio
Acoplamento executor ↔ subclassesMédio (polimorfismo)Mínimo (apenas às anotações)
Adicionar novo formatoCriar subclasseCriar classe com @RelatorioConfig
Adicionar novo passoEditar superclasseAnotar método com @PassoRelatorio
Metadados do formatoEspalhados em métodosDeclarados em @RelatorioConfig

As anotações atuam como contratos declarativos: o executor descobre o que precisa fazer lendo metadados em tempo de execução, sem nenhum acoplamento estático às implementações concretas. Para adicionar um formato RelatorioXML, basta criar a classe com as anotações — o ExecutorRelatorio não precisa ser alterado.
