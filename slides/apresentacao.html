🔴 Definição do Problema

Sistema de Geração de Relatórios

Uma empresa precisa gerar relatórios financeiros em 3 formatos: PDF, HTML e CSV. O fluxo de geração é sempre o mesmo — só o formato muda.

📄

PDF

Impressão e arquivamento formal

🌐

HTML

Visualização em portais web internos

📊

CSV

Importação em planilhas e BI

Fluxo invariante: Coletar dados → Processar → Formatar cabeçalho → Formatar corpo → Formatar rodapé → Exportar
Apenas os passos de formatação mudam entre os formatos.

A solução ingênua e seus problemas

RelatorioPDF.java public void gerar() { // Passo 1 — DUPLICADO coletarDados(); // Passo 2 — DUPLICADO processarDados(); formatarPDF(); // único // Passo 6 — DUPLICADO exportar(); }
RelatorioHTML.java public void gerar() { // Passo 1 — DUPLICADO ❌ coletarDados(); // Passo 2 — DUPLICADO ❌ processarDados(); formatarHTML(); // único // Passo 6 — DUPLICADO ❌ exportar(); }
  • 🔴
    Violação do DRY
    3 cópias dos passos 1, 2 e 6
  • 🔴
    Violação do OCP
    Novo passo = editar 3 arquivos
  • 🔴
    Sem garantia de ordem
    Cada classe pode omitir um passo
  • 🔴
    Alto risco de bug
    Corrigir em 1 lugar e esquecer os outros 2

✅ Padrão GoF

O que é o Template Method?

Definição (GoF): "Define o esqueleto de um algoritmo em uma operação, postergando alguns passos para subclasses. Permite que subclasses redefinam certos passos sem alterar a estrutura do algoritmo."
🏗️

Classe Abstrata

Define o método template (final) e implementa os passos fixos

🧩

Métodos Abstratos

Passos variáveis — subclasses são obrigadas a implementar

🪝

Hook Methods

Passos opcionais com implementação padrão vazia. Subclasse decide se participa

🔒

Invariante Garantido

final impede que a ordem dos passos seja alterada por subclasses

☕ Versão 2 — Código

Template Method na prática

RelatorioGerador.java public abstract class RelatorioGerador { // TEMPLATE — ninguém muda a ordem! public final void gerarRelatorio() { coletarDados(); // fixo processarDados(); // fixo formatarCabecalho(); // abstract formatarCorpo(); // abstract incluirMarcaDagua(); // hook formatarRodape(); // abstract exportar(); // fixo } protected abstract void formatarCabecalho(); protected abstract void formatarCorpo(); protected abstract void formatarRodape(); // Hook — implementação padrão vazia protected void incluirMarcaDagua() { } }
RelatorioPDF.java public class RelatorioPDF extends RelatorioGerador { @Override protected void formatarCabecalho() { // lógica específica PDF println("RELATÓRIO PDF LANDSCAPE"); } @Override protected void formatarCorpo() { // lógica específica PDF } @Override protected void formatarRodape() { println("Página 1 de 1 | PDF/A"); } // Sobrescreve o hook! @Override protected void incluirMarcaDagua() { println("CONFIDENCIAL"); } }

🪝 Hook Method

Extensão opcional com Hook Methods

Hooks são passos com implementação padrão que subclasses podem sobrescrever se quiserem. Permitem pontos de extensão sem obrigar implementação.

Superclasse — Hook vazio // Padrão: não faz nada protected void incluirMarcaDagua() { // hook vazio }
RelatorioPDF — sobrescreve @Override protected void incluirMarcaDagua() { println("CONFIDENCIAL"); // ✅ }
  • 📄
    RelatorioPDF
    Sobrescreve → adiciona "CONFIDENCIAL"
  • 🌐
    RelatorioHTML
    Não sobrescreve → sem marca d'água
  • 📊
    RelatorioCSV
    Não sobrescreve → sem marca d'água
💡

Por que hooks são poderosos?

A subclasse decide se quer participar de um passo do algoritmo — sem quebrar o contrato da superclasse.

⚡ Versão 3 — Motivação

Por que ir além? Reflexão e Anotações

Na Versão 2, o método template ainda está acoplado aos nomes dos métodos em tempo de compilação:

Versão 2 — acoplamento formatarCabecalho(); // nome fixo em código formatarCorpo(); // nome fixo em código formatarRodape(); // nome fixo em código
⚠️

Problema remanescente

A superclasse conhece os nomes dos métodos das subclasses. Para renomear um método é preciso atualizar a superclasse e todas as subclasses.

🚀

Solução: Anotações + Reflexão

O executor descobre os passos via @PassoRelatorio — sem conhecer os nomes nem as classes concretas.

🏷️ Anotações Criadas

Duas anotações próprias

PassoRelatorio.java @Retention(RUNTIME) @Target(METHOD) public @interface PassoRelatorio { // Ordem de execução int ordem(); // Descrição legível String descricao() default "Passo"; // Obrigatório ou hook? boolean obrigatorio() default true; }

Marca e ordena métodos do algoritmo

RelatorioConfig.java @Retention(RUNTIME) @Target(TYPE) public @interface RelatorioConfig { // Nome amigável do formato String nome(); // Extensão do arquivo String extensao(); // Versão do gerador String versao() default "1.0"; }

Declara metadados da classe

☕ Versão 3 — Aplicação

Anotações nas classes

RelatorioPDF.java @RelatorioConfig( nome = "Relatório PDF", extensao = "pdf", versao = "2.1" ) public class RelatorioPDF extends RelatorioGerador { @PassoRelatorio(ordem=3, descricao="Cabeçalho PDF") public void formatarCabecalho() { ... } @PassoRelatorio(ordem=4, descricao="Corpo PDF") public void formatarCorpo() { ... } @PassoRelatorio(ordem=5, descricao="Marca d'água", obrigatorio=false) public void incluirMarcaDagua() { ... } @PassoRelatorio(ordem=6, descricao="Rodapé PDF") public void formatarRodape() { ... } }
ExecutorRelatorio.java — usa reflexão public void executar(RelatorioGerador g) { // 1. Lê @RelatorioConfig da classe RelatorioConfig cfg = classe.getAnnotation(RelatorioConfig.class); // 2. Descobre passos anotados List<Method> passos = descobrirPassos(classe); // 3. Ordena por @PassoRelatorio.ordem passos.sort(Comparator .comparingInt(m -> m.getAnnotation(PassoRelatorio.class) .ordem())); // 4. Invoca dinamicamente! for (Method m : passos) { m.setAccessible(true); m.invoke(g); // sem conhecer o nome! } }

🔗 Acoplamento

Como reduz o acoplamento

❌ Versão 2 — acoplado aos nomes

Template chama formatarCabecalho(), formatarCorpo() — nomes fixos no código da superclasse

✅ Versão 3 — desacoplado

Executor descobre tudo via @PassoRelatorio — não conhece nem os nomes, nem as classes concretas

// Versão 3: executor usa reflexão for (Method m : passos) { m.invoke(g); // ✅ sem nome fixo } // Adicionar RelatorioXML? // Só criar a classe com @! // Executor NÃO muda.
Acoplamento Versão 3: ExecutorRelatorio depende apenas de @PassoRelatorio e RelatorioGerador. Não depende de RelatorioPDF, RelatorioHTML nem RelatorioCSV.
